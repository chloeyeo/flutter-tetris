## Directory Purposes

**`lib/`:**
- Purpose: 100% of the Dart application source. Flat structure — no subdirectories (no `lib/models/`, `lib/widgets/`, `lib/services/` split).
- Contains: Widgets (StatefulWidget/StatelessWidget), a plain model class (`Piece`), theming data (`TetrisSkin`), and two singleton service wrappers.
- Key files: `board.dart` (game engine + main screen, read this first to understand the app), `values.dart` (shared constants, read this second).

**`test/`:**
- Purpose: Automated test location per Flutter convention (`flutter test` scans this directory).
- Contains: A single, unmodified `flutter create` template test (`widget_test.dart`) that references a counter-app UI that does not exist in this codebase. There are no tests for `Piece`, `GameBoard` game logic, or `TetrisSkin`.
- Key files: `widget_test.dart` — needs replacing/rewriting to test the actual app before it provides any value.

**`assets/`:**
- Purpose: Static assets bundled into the app, declared in `pubspec.yaml` under `flutter: assets:`.
- Contains: App icon PNG (used only at build time by `flutter_launcher_icons`, not loaded at runtime) and WAV sound effects loaded at runtime via `AssetSource` in `SoundService`.
- Key files: `assets/sounds/*.wav` (referenced by string path from `TetrisSkin.landSound`/`clearSound` fields in `lib/skins.dart`).

**`android/`, `ios/`, `macos/`, `windows/`, `linux/`, `web/`:**
- Purpose: Platform-specific wrapper projects generated by `flutter create`, required to build/run on each target OS.
- Contains: Native project files (Gradle/Kotlin for Android, Xcode project for iOS/macOS, CMake for Windows/Linux, HTML/JS scaffolding for web).
- Key files: `android/app/src/main/AndroidManifest.xml` (mentioned in README as configured for Skia-fallback rendering), `android/app/src/main/kotlin/app/chloeyeo/tetris/` (package namespace for the Android app).
- Note: `AdService` currently throws `UnsupportedError` for any non-Android platform (`lib/ad_service.dart:19-33`), so iOS/desktop/web builds will crash if ads are invoked despite these platform folders existing.

**`build/`, `.dart_tool/`:**
- Purpose: Generated build artifacts and tool caches.
- Generated: Yes.
- Committed: No (present in `.gitignore`).

## Key File Locations

**Entry Points:**
- `lib/main.dart`: App bootstrap — `main()` initializes ads then calls `runApp(MyApp())`.

**Configuration:**
- `pubspec.yaml`: Dependencies (`google_mobile_ads`, `shared_preferences`, `audioplayers`, `cupertino_icons`), asset declarations, launcher icon config, Dart SDK constraint (`^3.11.5`).
- `analysis_options.yaml`: Lint rules (extends `package:flutter_lints/flutter.yaml`).
- `.metadata`: Flutter-tool-managed project metadata (do not hand-edit).

**Core Logic:**
- `lib/board.dart`: Game loop, collision/landing/line-clear, scoring, gesture handling, main UI composition.
- `lib/piece.dart`: Tetromino shape/rotation/movement logic.
- `lib/values.dart`: Board dimensions and shared enums — check here first when changing grid size or adding a new tetromino-related constant.

**Testing:**
- `test/widget_test.dart`: Only test file present; currently stale/non-functional for this app (see Directory Purposes above).

## Naming Conventions

**Files:**
- `snake_case.dart` throughout (e.g., `ad_service.dart`, `piece_preview.dart`, `skin_gallery.dart`) — standard Dart file naming.
- Service wrapper files are suffixed `_service.dart` (`ad_service.dart`, `sound_service.dart`).
- No test-file-per-source-file convention established yet (only one, unrelated test file exists).

**Classes/Types:**
- `PascalCase` for classes and enums (`GameBoard`, `Piece`, `TetrisSkin`, `SkinType`, `Tetromino`, `Direction`).
- Private State classes prefixed with underscore per Flutter convention: `_GameBoardState`, `_SkinGalleryState`.
- Enum values use `PascalCase`/short-form matching domain terms: `Tetromino.L`, `Tetromino.J`, `SkinType.y2k`, `SkinType.chalkboard`.

**Variables/Fields:**
- `camelCase` for all fields/locals/methods (`currentPiece`, `gameBoard`, `checkCollision`, `rowLength`).
- Private instance fields prefixed with underscore (`_bannerAd`, `_isBannerLoaded`, `_horizontalAccumulator`, `_adService`).
- Boolean flags prefixed with `is`/`can` (`_isBannerLoaded`, `_isInitialized`, `canHold`, `gameOver`).

**Directories:**
- No custom subdirectory naming pattern inside `lib/` — currently flat with no subdirectories at all.

## Where to Add New Code

**New Game Mechanic (e.g., new scoring rule, combo system):**
- Primary code: `lib/board.dart` (extend `_GameBoardState` — e.g., add fields alongside `currentScore`, logic alongside `clearLines()`/`checkLanding()`).
- Tests: `test/` — currently no game-logic test infrastructure exists; would need a new test file (e.g., `test/board_test.dart`) instantiating `_GameBoardState` logic directly or via `WidgetTester`.

**New Tetromino Behavior / Rotation System Change:**
- Implementation: `lib/piece.dart` (add cases to `rotatePiece()`'s per-type switch, or extend `piecePositionIsValid`).
- Shared constants: `lib/values.dart` if adding new `Tetromino` or `Direction` enum values (also requires updating `tetrominoColors` map and every `TetrisSkin.colors`/`emojis` map in `lib/skins.dart`, plus `PiecePreview._getShapeCoords()` in `lib/piece_preview.dart`).

**New Skin/Theme:**
- Implementation: `lib/skins.dart` — add a new `SkinType` enum value, a new static `TetrisSkin` instance with `colors`/`emojis`/background/grid/text colors, and a case in `TetrisSkin.getSkin()`.
- Assets (if adding sounds): place WAV files in `assets/sounds/` and declare them via the existing `assets/sounds/` glob already in `pubspec.yaml` (no per-file declaration needed since the whole folder is included).
- UI: no changes needed to `SkinGallery` (`lib/skin_gallery.dart`) since it iterates `SkinType.values` generically — new skins appear automatically in the gallery grid.

**New External Service Integration (e.g., leaderboard, analytics):**
- Implementation: create a new `lib/<name>_service.dart` following the existing singleton pattern (private constructor + static `_instance` + `factory` constructor), matching `lib/ad_service.dart`/`lib/sound_service.dart`.
- Wiring: instantiate as a `final` field in `_GameBoardState` (`lib/board.dart`) alongside `_adService`/`_soundService`.

**Utilities:**
- Shared helpers: none currently exist as a separate file — flat-index math (`row`/`col` from a flat position) is duplicated inline in `lib/board.dart` and `lib/piece.dart` rather than centralized. If adding a new utility, create `lib/board_utils.dart` (or similar) rather than continuing to duplicate logic inline (see `ARCHITECTURE.md` Anti-Patterns section).

## Special Directories

**`build/`:**
- Purpose: Compiled output for all platform targets.
- Generated: Yes.
- Committed: No.

**`.dart_tool/`:**
- Purpose: Dart/Flutter package resolution cache and tool state.
- Generated: Yes.
- Committed: No.

**`.idea/`:**
- Purpose: JetBrains IDE (Android Studio/IntelliJ) project settings.
- Generated: Yes (IDE-managed).
- Committed: Present in repo (contains `caches/`, `libraries/`, `runConfigurations/`) — typically should be git-ignored but currently exists in the working tree.

**`android/.gradle/`, `android/.kotlin/`:**
- Purpose: Gradle/Kotlin build caches for the Android platform subproject.
- Generated: Yes.
- Committed: No (should be git-ignored).

**`.planning/`:**
- Purpose: GSD (this tool's) planning artifacts — codebase maps, phase plans, etc.
- Generated: Yes (by GSD commands).
- Committed: Typically yes, as project planning history.
